Chipload 0.30.0 user guide

Command line

Every command takes --json: one JSON object instead of text (see Scripting). chipload --help and chipload COMMAND --help print the same help in the terminal.

chipload inspect

Dump units, entities, contours and issues of a DXF, an SVG or a project

chipload inspect <FILE> [OPTIONS]
ArgumentMeaning
<FILE>A .dxf or .svg drawing or a .chipload project.
--units <UNITS>Units of a DXF that does not declare them. One of: mm, inch.
--px-per-inch <PX_PER_INCH>Pixels per inch of an SVG that gives no real size: 96 (Inkscape, browsers) or 72 (older Illustrator)

chipload new

Create an empty project, to draw in or import a DXF into later (update --from)

chipload new [OPTIONS]
ArgumentMeaning
-o, --output <OUTPUT>The project to write (.chipload) Required.
--machine <MACHINE>The machine profile to start from (default: your default machine)

chipload import

Create a project from a DXF or an SVG

chipload import <DXF> [OPTIONS]
ArgumentMeaning
<DXF>The DXF or SVG (.svg, .svgz)
--units <UNITS>Units of a DXF that does not declare them. One of: mm, inch.
--px-per-inch <PX_PER_INCH>Pixels per inch of an SVG that gives no real size: 96 (Inkscape, browsers) or 72 (older Illustrator)
-o, --output <OUTPUT>The project to write (.chipload) Required.
--machine <MACHINE>The machine profile to start from (default: your default machine)

chipload update

Replace a project’s imported drawing with a new version of the DXF or SVG

chipload update <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--from <FROM>The new DXF or SVG. Required.
--units <UNITS>Units of the new DXF, if they differ from the last import. One of: mm, inch.
--px-per-inch <PX_PER_INCH>Pixels per inch of an SVG without a real size, if they differ from the last import.
--dxf <DXF>Which DXF of the project (as dxf list shows); needed when it has several.
-o, --output <OUTPUT>Where to write the result; default: the project itself.

chipload plan

Plan a project’s toolpath without writing G-code

chipload plan <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--setup <ID>Only this setup (as setup list numbers it); default: every setup for run, the active one otherwise (docs/specs/setups.md §8)
--part <ID>Only this part (as part list numbers it), as if every other part were switched off; may be given more than once (docs/specs/part-export.md) Repeatable.
--set <PATH=VALUE>For this run only: set a project value by path, e.g. stock.thickness=18 (see chipload set). The project file isn’t changed. Repeatable.

chipload run

Generate checked G-code from a project

chipload run <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
-o, --output <OUTPUT>Where to write the G-code. With several tools and one file per tool: part.nc gives part-1-T1.nc, part-2-T2.nc, … Required.
--tool-change <TOOL_CHANGE>For this run only: one file per tool, or one file with M6 tool changes (default: the project’s machine setting) One of: files (One G-code file per tool group), program (One file with T<n> M6 at each tool change).
--no-sheetDon’t write the setup sheet (by default part-sheet.html next to part.nc)
--sheet-units <UNITS>The setup sheet’s lengths and feeds: mm (default) or inch. The G-code’s units are the machine’s (machine.gcode_units) One of: mm, inch.
--sheet-lang <LANG>The setup sheet’s language (default: English). The command line itself stays English. One of: en, de, fr, es, it, sv.
--setup <ID>Only this setup (as setup list numbers it); default: every setup for run, the active one otherwise (docs/specs/setups.md §8)
--part <ID>Only this part (as part list numbers it), as if every other part were switched off; may be given more than once (docs/specs/part-export.md) Repeatable.
--set <PATH=VALUE>For this run only: set a project value by path, e.g. stock.thickness=18 (see chipload set). The project file isn’t changed. Repeatable.

chipload simulate

Simulate the material a project’s program removes (docs/specs/simulation.md): print the numbers and write a shaded top view (PNG). The job is generated and checked as by run; no G-code is written

chipload simulate <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
-o, --output <OUTPUT>Where to write the image (.png); default: the project’s name with -sim.png.
--cell <CELL>Cell size, mm (default: automatic, from the stock’s size)
--no-imagePrint the numbers only.
--after <N>The stock after only the first N moves of the program (docs/specs/playback.md §5), for tests and scripts.
--setup <ID>The setup to simulate (as setup list numbers it); default: the active one.
--set <PATH=VALUE>For this run only: set a project value by path, e.g. stock.thickness=18 (see chipload set). The project file isn’t changed. Repeatable.

chipload sheet

chipload sheet <PROJECT> [OPTIONS]
ArgumentMeaning

-o, --output <OUTPUT>Where to write the sheet (.html) Required.
--gcode <GCODE>The G-code the sheet is for, as given to run -o, for its file names (default: the project’s name with the post’s extension)
--tool-change <TOOL_CHANGE>For this sheet only: one file per tool, or one file with M6 tool changes. One of: files (One G-code file per tool group), program (One file with T<n> M6 at each tool change).
--units <UNITS>Its lengths and feeds: mm (default) or inch. The G-code’s units are the machine’s (machine.gcode_units) One of: mm, inch.
--lang <LANG>Its language (default: English). The command line itself stays English. One of: en, de, fr, es, it, sv.
--setup <ID>Only this setup (as setup list numbers it); default: every setup for run, the active one otherwise (docs/specs/setups.md §8)
--part <ID>Only this part (as part list numbers it), as if every other part were switched off; may be given more than once (docs/specs/part-export.md) Repeatable.
--set <PATH=VALUE>For this run only: set a project value by path, e.g. stock.thickness=18 (see chipload set). The project file isn’t changed. Repeatable.

chipload render

Render a toolpath JSON (as plan --json prints under “program”) through a post-processor. For testing posts; the output is NOT checked, use run to cut

chipload render <PROGRAM> [OPTIONS]
ArgumentMeaning
<PROGRAM>Toolpath JSON file.
--post <POST>Built-in post-processor. Default: grbl.

chipload check

Check a G-code program against a project’s stock, safe height and machine limits

chipload check <GCODE> [OPTIONS]
ArgumentMeaning
<GCODE>G-code file to check.
--job <JOB>The project (or job) the program was generated from. Required.
--tool <TOOL>The project’s tool that cuts this program, for its stock margin (one file of a set written one file per tool). Default: the largest tool the project uses.

chipload op

Change an operation of a project

chipload op tool

Set the tool an operation cuts with (docs/specs/tool-per-operation.md §7). The tool must be in the project: copy one in from your library with tool use

chipload op tool <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--op <OP>The operation’s number as the app lists it (1 = first; get and set paths count from 0) Required.
--tool <TOOL>The tool’s id in the project. Required.
-o, --output <OUTPUT>Where to write the result; default: the project itself.

chipload op add-rest

Add a rest pass to a pocket (docs/specs/rest-passes.md): a smaller endmill that clears what the pocket’s tool (or its last pass’s) leaves, in the pocket’s shapes and depths. It is cut after the run of pockets with the pocket’s tool

chipload op add-rest <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--op <OP>The pocket’s number as the app lists it (1 = first; get and set paths count from 0) Required.
--tool <TOOL>The smaller tool’s id in the project. Required.
-o, --output <OUTPUT>Where to write the result; default: the project itself.

chipload op add-floor

Give a V-carve a floor pass (docs/specs/vcarve-wide-strokes.md §4): an end mill that clears the floor between the walls of strokes too wide to carve from their centre line, cut before the V-carve. Replaces the floor pass it had

chipload op add-floor <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--op <OP>The V-carve’s number as the app lists it (1 = first; get and set paths count from 0) Required.
--tool <TOOL>The end mill’s id in the project. Required.
-o, --output <OUTPUT>Where to write the result; default: the project itself.

chipload op remove-floor

Take a V-carve’s floor pass away (docs/specs/vcarve-wide-strokes.md §4)

chipload op remove-floor <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--op <OP>The V-carve’s number as the app lists it (1 = first) Required.
-o, --output <OUTPUT>Where to write the result; default: the project itself.

chipload op add-surface

Add a surface (docs/specs/surfacing.md): the whole stock taken down flat with a wide endmill, in straight passes back and forth, first in the active part. Flattens the spoilboard or faces the stock

chipload op add-surface <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--tool <TOOL>The endmill’s id in the project; default: the widest endmill.
--depth <DEPTH>How much comes off the top; default 0.5 mm.
-o, --output <OUTPUT>Where to write the result; default: the project itself.

chipload op rest-pass

A pocket’s rest passes (docs/specs/rest-passes.md): without –pass, list them; with it, change, turn off or on, or remove one

chipload op rest-pass <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--op <OP>The pocket’s number as the app lists it (1 = first) Required.
--pass <PASS>Which pass: 1 for the first (shown as 3.1 for operation 3)
--tool <TOOL>The tool’s id in the project: an endmill smaller than the tool before it.
--feed <FEED>
--plunge-feed <PLUNGE_FEED>
--step-down <STEP_DOWN>
--stepover <STEPOVER>A fraction of the tool’s diameter, at most 1.
--enabled <ENABLED>Cut it (true) or keep it without cutting (false) One of: true, false.
--removeRemove the pass; the passes after it rest after the tool before it.
-o, --output <OUTPUT>Where to write the result; default: the project itself.

chipload op corners

ArgumentMeaning
<PROJECT>The project (.chipload)

chipload op corner

Give one corner of a profile or pocket its own bone, whatever the operation’s corners say (docs/specs/dogbone-per-corner.md): --bone none keeps it round. op corners lists the corners

chipload op corner <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--op <OP>The operation’s number as the app lists it (1 = first) Required.
--at <AT>The corner, X,Y in drawing coordinates (a plain number is mm)
--bone <BONE>What the corner gets. One of: none, dogbone, tbone.
--along <ALONG>With a T-bone: the wall it runs along (the notch is in the other); default longer. One of: longer, shorter.
--as-operationRemove the corner’s own choice: it gets what the operation gives every corner.
--resetRemove every corner’s own choice.
-o, --output <OUTPUT>Where to write the result; default: the project itself.

chipload op tab

Place a profile’s tabs by hand (docs/specs/tabs-by-hand.md): add a tab at a point, or remove the one there. The first on a contour keeps that contour’s other tabs where Chipload put them. --even spaces one contour’s tabs evenly again, --reset all

chipload op tab <PROJECT> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
--op <OP>The operation’s number as the app lists it (1 = first) Required.
--at <AT>The point, X,Y in drawing coordinates (a plain number is mm): on or near the contour, within a tool diameter.
--removeRemove the tab nearest to –at.
--evenSpace the tabs of the contour nearest to –at evenly again.
--resetSpace every contour’s tabs evenly again.
-o, --output <OUTPUT>Where to write the result; default: the project itself.

chipload shape

Draw in a project: add, change or delete circles, rectangles and polylines

chipload shape add

Add a drawn shape; prints its id

chipload shape add <PROJECT> <KIND> [OPTIONS]
ArgumentMeaning
<PROJECT>The project (.chipload)
<KIND>One of: circle, rectangle, polyline, polygon.
--center <CENTER>Centre “X,Y” (circle, rectangle, polygon)
--radius <RADIUS>A circle’s radius; a polygon’s, to its corners.
--sides <SIDES>A polygon’s number of sides, 3 to 1000.
--across-flats <ACROSS_FLATS>A polygon’s size across its flats (twice the radius to the middle of a side), in place of –radius.
--length <LENGTH>Along the rectangle’s own X axis.
--width <WIDTH>Along the rectangle’s own Y axis.
--angle-deg <ANGLE_DEG>Rotation about the centre (a polygon: its first corner’s angle from +X), degrees, counter-clockwise.
--corner-radius <CORNER_RADIUS>The radius of the rectangle’s corners, at most half its shorter side (default 0: sharp)
--points <POINTS>Polyline points “X,Y X,Y …”.
--bulges <BULGES>Polyline bulges “B B …”, one per segment: tan(sweep / 4) as in DXF, 0 straight, 1 a counter-clockwise half circle, -1 clockwise (default: all straight)
--openThe polyline doesn’t return to its first point.
--closedThe polyline returns to its first point (the default for new ones)
--layer <LAYER>
--name <NAME>Its name in the Browser; “” takes the name away.
--construction <CONSTRUCTION>Construction geometry: shown and snapped to, never cut (--construction false makes it an ordinary shape again) One of: true, false.
-o, --output <OUTPUT>Where to write the result; default: the project itself.
